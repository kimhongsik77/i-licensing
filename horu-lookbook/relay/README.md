# 툴 이어달리기(Relay) 시스템 — 쉬운 설명

**한 줄 요약:** 무료 툴 크레딧이 떨어지면, 작업 내용(바통)을 다음 툴에 넘겨서 처음부터가 아니라 *이어서* 작업합니다.

| 파일 | 비유 | 역할 |
|---|---|---|
| `style_card.yaml` | 정답지 | 호루 색·서체·무드·금지사항. 모든 툴이 먼저 적용 (D 드라이브 학습 후 확정) |
| `tool_ladder.yaml` | 주자 순서 | Canva → Adobe → Figma → 이미지AI, 크레딧 잔량, 현재 단계(Lv) |
| `jobs/J001.json` | 바통 | 작업별 지시문·레퍼런스·진행상황·결과물 |
| `handoff/*.md` | 바통 전달 메모 | 툴이 바뀔 때 자동 생성되는 인계서 |
| `relay.py` | 장부 담당자 | 누가 뛸 차례인지 정하고 바통을 기록 |

## 흐름
1. `new` 작업 카드 생성 → 1번 툴 배정
2. 작업하며 `progress`로 중간 결과 기록
3. 크레딧 소진 시 `credit-out` → 인계서 자동 생성 → 다음 툴로 전환 (Lv.1: 자동 전환 후 알림)
4. 끝나면 `done --qa pass|fail` → 품질 성적 누적 → 단계 상향/하향 *제안* (확정은 사장님)
5. 다음 달 크레딧이 차면 `refill`로 복귀

## 단계 (사장님 승인으로만 변경)
| Lv | 동작 | 상향 조건 |
|---|---|---|
| 0 | 전환마다 승인 | 무사고 전환 5회 |
| **1 (현재)** | 자동 전환 + 알림 | 품질검사 10연속 통과 |
| 2 | 완전 자동 | — |
