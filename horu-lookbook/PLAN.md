# HÖRU 룩북·목업 자동화 + 카테고리 확장 + 품질 업그레이드 자동화 계획

작성: 2026-11-20 · 기준 자료: Canva「HÖRU SS27 Lookbook」(8p, 2026-11 작업), 「0_HÖRU_브랜드소개서_제작지침 v1.0」(2026-08-13), 「HÖRU_StyleGuide_2026(최종)」, 리뉴얼 README(2026-08-04)

## 0. 결론

**SS27 룩북 8p를 템플릿 8종 + 데이터 시트 1장으로 표준화하고, ‘생성 → 목업 합성 → 레이아웃 → 3단 QA → 결함 학습’ 파이프라인으로 자동화한다.**
- 1단계(4주): 패션(애슬레저·영캐주얼) + 잡화 2종(가방·캡) + 라이프스타일 1종(텀블러)로 파일럿
- 품질은 “점수 + 블로커” 방식 자동 QA 게이트로 관리하고, 실패 로그를 매주 집계해 규칙·프롬프트·템플릿을 업그레이드하는 루프를 둔다
- **착수 전 결정 1건 필수**: 가상모델(AI) 룩북을 허용할지 — 현행 지침 v1.0과 SS27 실제 작업이 충돌함 (§1-2)

## 3. 자동화 파이프라인

```
[① 브리프 시트] → [② 이미지 생성/촬영 자산] → [③ 목업 합성] → [④ 레이아웃 자동배치] → [⑤ 3단 QA 게이트] → [⑥ 배포·버전기록]
      ▲                                                                                    │
      └──────────────── [⑦ 결함 로그 → 주간 규칙/프롬프트/템플릿 업그레이드] ◄─────────────┘
```

| 단계 | 하는 일 | 도구 (현재 연결된 것 우선) | 산출물 | 리스크 |
|---|---|---|---|---|
| ① 브리프 | 1행=1페이지: 템플릿·라인·모델ID·씬·SKU·카피 | Google Sheets | 브리프 시트 | 카피 미확정 상태로 진행 → 지침 §4-3처럼 텍스트 먼저 확정 |
| ② 생성 | 모델 착용컷·씬 생성 / 실사 자산 선별 | 현재 SS27에 쓴 이미지 생성 툴(확인 필요), 실사 Product/ 폴더 | 원본 컷 | 얼굴·로고 왜곡 |
| ③ 목업 | 누끼, 배경 확장, 로고 합성(자수·각인·스티커·라벨) | Adobe(배경제거·Generative Expand), Canva 배경제거 | 목업 PNG | 로고 비율 변형 |
| ④ 레이아웃 | 템플릿 8종에 시트 데이터 자동 채움 | Canva 브랜드 템플릿 + 데이터 채우기(Autofill) | 룩북 초안 | Autofill은 Canva 상위 플랜 기능 — 사용 가능 여부 확인 필요 |
| ⑤ QA | 자동(스크립트) → AI 비전 → 사람 | `scripts/qa_check.py` + 비전 체크리스트 | QA 리포트 | 자동 검사만 믿는 ‘자동화 과신’(지침 리포트 지적사항) |
| ⑥ 배포 | 프리셋별 내보내기, README 버전 기록 | Canva export, Drive | 웹 16:9 / SNS 4:5 / 1:1 / 인쇄 A4 | 버전 혼선 |
| ⑦ 업그레이드 | 실패 패턴 집계 → 룰·프롬프트·템플릿 개정 | QA JSON 로그 + 주간 리포트 | 규칙 v+1 | 개정 후 회귀 품질 저하 |

## 7. 퀄리티 점검 체계 (3단 게이트)

### 7-1. 게이트 구성

| 게이트 | 담당 | 검사 내용 | 판정 |
|---|---|---|---|
| G1 자동 | `qa_check.py` | 팔레트 ΔE, 폰트, 금지어·좌표, C-COPY, 해상도, 비율, 클리핑, 선명도, 모델ID, 필수필드 | 100점 중 85↑ **AND** 컴플라이언스 블로커 0건 |
| G2 AI 비전 | 이미지 판독 체크리스트 | 손가락·얼굴 왜곡, 깨진 텍스트, 로고 비율·보호공간, 랜드마크·경쟁사 간판, 모델 얼굴 일관성 | 결함 0건 |
| G3 사람 | 담당자 | 무드(북유럽 미니멀) 적합성, 상품 표현 정확도, 최종 PDF/렌더 확인 | 승인 |

### 7-2. 점수 배분 (`config/brand_rules.yaml > scoring`)

| 영역 | 배점 | 블로커 여부 |
|---|---|---|
| 브랜드 (컬러·폰트) | 30 | — |
| 컴플라이언스 (국가명·경쟁사·C-COPY) | 25 | **블로커** — 1건이라도 실패 시 점수 무관 FAIL |
| 이미지 품질 | 25 | — |
| 일관성 (모델) | 10 | — |
| 정보 (필수 필드) | 10 | — |

### 7-3. 실행 예 (데모 manifest)

```bash
pip install pillow pyyaml
python3 horu-lookbook/scripts/qa_check.py \
  --manifest horu-lookbook/samples/sample_manifest.yaml \
  --rules horu-lookbook/config/brand_rules.yaml \
  --spec horu-lookbook/config/lookbook_spec.yaml \
  --out horu-lookbook/samples/qa_report.md
# 결과: 86.5점이지만 'Sweden' 블로커 1건 → FAIL (exit 1)
```

## 8. 업그레이드 자동화 (지속 개선 루프)

| 주기 | 자동 작업 | 산출물 | 사람이 할 일 |
|---|---|---|---|
| 매 생성 | QA JSON 로그 누적 (페이지·영역·실패사유) | `qa_log/*.json` | — |
| 매주 | 실패 사유 Top5 집계 → 원인 분류(프롬프트/자산/템플릿/규칙) | 주간 품질 리포트 | 개정안 승인 |
| 매주 | 개정안 반영: 금지어 추가, 프롬프트 네거티브 추가, 템플릿 여백 수정 | brand_rules / 프롬프트 v+1 | — |
| 개정 시 | **골든셋 회귀 테스트**: 합격 이력 페이지 20장 재검사해 통과율 하락 여부 확인 | 회귀 리포트 | 하락 시 롤백 결정 |
| 매월 | 카테고리별 통과율·리드타임 KPI 대시보드 갱신 | KPI 표 | 다음 달 우선 카테고리 결정 |
| 분기 | 시즌 무드 업데이트 (SS→FW 팔레트 내 톤 조정, 씬 라이브러리 교체) | 시즌 프리셋 | 시즌 콘셉트 확정 |

업그레이드 원칙
1. 규칙은 `brand_rules.yaml` 한 곳에서만 수정 — 지침 §0 “단일 기준” 원칙과 동일
2. 개정은 반드시 회귀 테스트 통과 후 반영 (개선이 다른 곳을 깨뜨리는 것 방지)
3. 같은 결함 3회 이상 → 자동검사(G1) 항목으로 승격
